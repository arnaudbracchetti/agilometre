Named constructor / static factory method

Anatomie

export class MaClasse {
  private constructor(/* champs */) { /* ? validation ici ? */ }

  static creer(/* args bruts */): MaClasse {
    // ? validation ici ?
    return new MaClasse(/* ... */);
  }

  static reconstituer(/* args déjà valides */): MaClasse {
    return new MaClasse(/* ... */);
  }
}

Checklist de revue

  1. Lister toutes les méthodes static qui appellent le constructeur privé.
  2. Localiser où vit la validation d'invariant : constructeur, ou une factory précise ?
  3. Si elle est dans une factory : chaque autre factory la rappelle-t-elle, ou existe-t-il un chemin silencieux qui la contourne ?
  4. Si un chemin la contourne délibérément (ex: recharger des données déjà validées), est-ce documenté, pas seulement implicite ?

Deux écoles

Valider dans le constructeur

Garantie structurelle : impossible de créer une instance invalide, quel que soit le chemin. Lève une exception → tout appelant doit gérer l'échec.

Valider dans la factory

Constructeur "muet". Permet de retourner un Result<T> au lieu de lever. Risque : une factory ajoutée plus tard peut oublier de revalider.

Vocabulaire

  • Named constructor — méthode statique nommée qui construit l'objet, en complément ou remplacement d'un constructeur public.
  • Invariant — une règle qui doit toujours être vraie pour qu'une instance soit valide (ex: un Niveau est toujours entre 1 et 4).
  • Result type — un objet qui encode succès/échec comme une valeur de retour normale, sans lever d'exception.
